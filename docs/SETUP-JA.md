# 公開リポジトリの設定手順

1. GitHubで新しい公開リポジトリを作成します。名称の例は `public-directory-audit` です。既存の非公開リポジトリを「公開」に変更してはいけません。
2. この一式から **PRIVATE-KEYファイルを除いた公開用フォルダー** のみを新しいリポジトリに登録します。秘密鍵はこのフォルダー内には含まれておりません。
3. GitHubの「Actions」では、ソフトウェアの模擬テストだけを実行します。リアルサイトの大量巡回は実行しません。
4. リポジトリ内の `public-key.pem` は**架空データを使うテスト専用**です。実際の調査に利用するには、別途安全な環境で RSA 3072 ビット以上の鍵ペアを生成し、対応する公開鍵をリポジトリ外へ置いて `RESEARCH_PUBLIC_KEY_PATH` で指定します。秘密鍵は公開リポジトリ、チャット、共有クラウド、GitHub の設定にアップロードしないでください。
5. `npm test` は、架空のサイトや模擬応答を使った安全性テストです。**実在サイトに対してアクセスを行いません。**
6. 実際の公開事業者データの取得やサイト検証には、事業用データ調査を許可する別の隔離されたLinux環境と、その利用料・無料枠の事前確認が必要です。個人用WindowsとGitHub Actionsでのサイト巡回はしません。
7. 調査結果の暗号ファイルは、Linuxなどの安全確認済み環境でのみ復号してください。感染の疑いがあるWindows PCで秘密鍵を使用しないでください。

## 現時点でできること

- プログラム構造、安全制限、暗号化、模擬判定の確認
- GitHubの無料の標準Linuxランナーを使ったソフトウェアテスト
- 独立環境へ移行するためのソース一式の保管

## 現時点でできないこと

- このリポジトリだけで継続的に月間・日間の大量営業先を無料収集すること
- フォームの存在から営業送信を法的に許可されたと判断すること
- 危険サイトへのアクセスを絶対に安全と保証すること

プログラムは本番システムと完全に分離されており、既存の顧客情報や非公開ソースを必要としません。
