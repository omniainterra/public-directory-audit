# OMNIASUM 米国向け在庫増強 — 最短完成の固定運用ルール

制定：2026-10-08
状態：**恒久的な作業方針**。今後の担当者・チャット・監査・引き継ぎに適用する。
適用範囲：米国向けの営業先調査、再分類、安全保管、送信可能在庫の補充。

## 優先順位（必ずこの順）

1. **既存資産から実用化する。** 既に保存済みの「フォーム確認済み・法規制審査前」候補から、重複・禁止・危険・身元・営業目的・州・サイト利用条件を整理する。追加の無差別巡回や全件再調査を先行条件にしない。
2. **開発の範囲を凍結する。** 未実装機能の追加や設計の作り直しではなく、稼働を止める実際の阻害要因だけを直す。修正には再現用の失敗テストと修正後の合格結果を必須とする。
3. **安全な保存基盤は並行作業にする。** Cloudflare Access/認証/暗号化/D1の検証を進めながら、過去成果物の**オフライン**再分類を止めない。ただし未認証の本番保存機能や実データアップロードは有効化しない。
4. **小規模な実測 → 検証 → 拡大。** 許可された少数の対象について、隔離された環境で安全・権限・法規制・料金を確認する。実サイト巡回は、件数・費用・権限を提示し個別承認を得たあとだけ実施する。小規模で動かない機能を大規模にしない。
5. **成果の測定方法を固定する。** 発見件数、Cron成功、監査件数、候補フォーム件数は完成条件ではない。正式仕様の全ゲートを満たし、重複なく増加した、**実際の送信可能なREADY件数**を最終成果とする。

## 絶対に短縮してはならない安全条件

- 最新の**承認済みCanonical Specification**が唯一の製品仕様正本。Outreachについては承認済み `OMNIASUM_Outreach_Engine_V2_Plan_2026-09-28.docx` の要求を尊重する。差異は一覧化し、勝手に解消したことにしない。
- 公式手順では米国送信前に**全50州の一次資料・対象チャンネル・連邦規制と適用/先占の審査、事業者個別のサイト規約とフォーム目的の証拠**が必要。未確認は `REVIEW`、禁止は `BLOCK`。フォームの発見だけでは `SEND` や `READY` にしない。
- フランスの在庫・抑制・送信履歴・DBを変更しない。米国の実送信を無断で有効にしない。二重送信と過去の送信履歴のすり抜けを禁止する。
- 金額提示と事前承認なしの**有料API・ブラウザー・GitHub Actions・Cloudflareプラン変更・実メール送信・大量外部通信・本番変更**は禁止。
- セキュリティ警告のあったWindows self-hosted Runnerを再起動しない。個人Windows端末を未知サイトへの大量巡回や秘密鍵の生成/保持に使わない。
- 公開GitHubのActionsは架空データを用いたソフトウェアテストのみ。実営業先・顧客情報・トークン・秘密鍵・非公開成果物をコミット、成果物公開、ログ表示しない。実データは権限が限定された非公開環境だけで処理する。
- Cloudflare本番の認証・署名・暗号化・D1実書込は、コードの模擬テストと別に検証する。制限をすり抜ける変更は禁止。
- 完成報告/本番反映は、該当要件と自動テストを１対１で照合し、回帰テスト・FR/EN隔離・Preview検証が合格するまでは行わない。

## 最初の実行単位

1. 既存在庫を現在のエクスポートと manifest で照合し、サイト・送信先・事業者識別の重複、除外、確認が必要な件数を計測する。**外部アクセスはしない**。
2. 既存50州リサーチ台帳の不足箇所を確定し、承認済み法規制ゲートを満たす根拠の調査・レビューを優先する。仮の法律分類で `READY` を増やさない。
3. Cloudflare Access と秘密情報管理を仕上げ、別途承認された架空１件のみで D1 の書込/読込を検査する。
4. 外部サイトの小規模読み取りを提案する場合は**対象件数、上限費用、隔離環境、権限、終了条件**を明示して事前承認を得る。
5. 最後に未調査分・過去失敗分の再調査を拡大し、毎日増加した審査済みREADYの件数を測定する。

**同じ説明・改善PRを繰り返さず、毎回「実データで前進した件数」「未解決の阻害要因」「次に必要な最小操作」の３点を報告する。**
